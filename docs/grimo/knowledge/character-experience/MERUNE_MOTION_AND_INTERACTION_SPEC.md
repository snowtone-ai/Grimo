## 1. 体験の目的と独自性

タスクを終えて訪れたとき、ユーザーが「気づいてくれた」「触れたことが伝わった」「自分から小さな返事をくれた」「静かに一緒にいられる」と感じること。**音楽=身体の意図の比喩**。音の有無やマイク入力を前提にしない。耳→顔→胸／支持→尾の順序は代表的な演技仮説であり、すべての場面で固定しない。触れた場合は接触箇所の局所ACKが先。

### 何を表現し、何をしてはいけないか

| 体験 | メルネ固有の身体表現 [DIR] | 失敗 |
| --- | --- | --- |
| 静かな待機 | 4足または自然な休息支持で耳の注意、ゆっくりした視線移動、控えめな呼吸、時には真の静止 | 音楽の拍子を常時打つ機械的同期、一定周期バウンス |

| 頭を撫でる | 接触した頭頂・耳根近傍の局所反応→眼瞼が緩む→頭をわずかに預ける | 頭を通り抜ける手、全身ぴょん跳ね |

| 困惑・境界 | 耳の小さな角度変化→接触側から引く→目で確認→穏やかに回復 | 攻撃や責め、無入力で悲しくなる |

## 2. パフォーマンス構造と入力契約

- **入力:** 有効なtap / slow stroke / continued stroke / release / cancel、画面上の接触位置・zone・側・方向・速度・継続時間、実在するTask/Calendar/Collection事実のみ。非取得の圧力・現実の音・顔の検出を偽造しない。
- **Attention:** ユーザーとの対話方向、実際の接触、利用可能な現物、小さな自主行為の間で移動。瞳と頭の協調。見続けない自由も必要。
- **Affect:** 喜び／集中／穏やかな好奇心／一瞬の驚き／控えめな境界。直前の感情を消さず次の入力を受ける。怒り・寂しさ・飢えの放置ペナルティは作らない。
- **Decision:** accept / lean / look / WAIT / resume / rest / mild boundary。毎入力にフル演技を選ばない。
- **Performance:** 接触局所ACK → 受容・意図 → 必要な支持確保 → 主要な顔・身体・四肢動作 → 耳／尾／胸の条件付き余韻 → settle → afterglow。割込みは現在姿勢／接地を保ったまま再選択。
- **Variation:** 行動の意味は一定、片耳の選択、視線の目的、休止・反応規模・反応の有無に文脈依存の差をつける。乱数で気まぐれに怖がらせない。

## 4. Motion-ready 3D anatomy

- **眼窩／瞼／口:** 視線・自然な瞬き・口の開閉に必要な可動域。大きなCanonical瞳・柔らかな頬の深さを失わない。Facial Morphまたは局所Rigを選択してよい。
- **耳:** 別々の耳根に局所可動性。広い内耳模様が裏返らず、金色の滴と毛が自然に追従。
- **胸のハープ:** 造形が胸と同じ空間の動作を受け、必要な内部リブのみ局所変化。器官全体を硬く取り外す構造にしない。接触の反応領域は独立。
- **体幹／脚:** 肩・臀部・短い足の曲がり、真の後躯支持、歩行の接点、軽い上体の傾き。見た目の接地が最優先。
- **巻き尾:** 根元／中間／先端の分散制御ができること。大きな輪と金線を守り、頭・背中・床との衝突を必要な範囲で防ぐ。
- **材料／模様:** 体表・尾表・胸部装飾のUVと模様が伸びすぎず、損失なく動く。

## 5. Stage / priority / evidence

1. **Identity baseline (Human):** 正面・3/4・側面・後方を採用済みCanonicalと比較。未知の背面はHuman判定。目と口の可愛さ、ハープ、耳、巻き尾。
2. **Rig reality (technical):** 既存GLBをBlenderに輸入し、bind pose・weights・初期姿勢・耳／尾／脚／胸変形を現物検査。表示が正しくても動くとは限らない。
3. **Minimal hero motion (Human + technical):** 「気づく→短い耳／視線の応答→静止」「頬を撫でられる→局所ACK→小さな寄り添い→余韻」を**無音・無VFX**でまず制作。支持と接触を見て必要ならRigへ戻る。
4. **Locomotion/seating:** 四足歩行→停止・支持、真の座位、自然な座位→立位。実演で接地点／尾根元を確認。
5. **Agency/continuity:** 誘い→WAIT→応答あり／なし、割込み、反復と静寂の変化。15–30秒＋2–5分の人間評価。
6. **Runtime:** glTF/GLB再読み込み、PlayCanvas / スマホPWAで顔・音無し演技・入力と同期・描画負荷を確認。

**Not a fixed clip list:** 行動ファミリーは必要なクリップ、レイヤー、Morph、procedural channelの組み合わせで実装してよい。細かいフレーム数や骨数、ループ周期をこの設計では捏造しない。
