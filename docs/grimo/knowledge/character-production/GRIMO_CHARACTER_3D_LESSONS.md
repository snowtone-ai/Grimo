## 1. デザイン段階で解くこと

**P: 2Dで可愛いことと、Tripo / Blender / Rig / Motionで安定して成立することは別のゲートである。** 可愛さを捨てて作りやすくするのではなく、承認前に曖昧な立体解釈を小さく試す。

各パーツについて、所属する身体、付け根、境目、厚み、前後関係、回転・圧縮する領域を図示する。顔・顎・首・胸・胴・脚・尾を、輪郭の塊だけでなく一頭の支持構造として説明できること。独立して動く耳・瞼・眼球・口内・脚・尾には、独立した制御領域と干渉を逃がす空間が必要。別mesh化は手段であって、全てをばらばらにするルールではない。

**H/O [E1,E2]:** 毛の量感を増す反復は、頭・首・胴が膨張し生物的に不自然というHuman不合格へ至った。高いシルエット一致率は救済にならなかった。小さい頭周りと大きい胴の関係、鼻より前へ出ない頭毛、顎ではなく首に所属する下側の毛が重要だった。

**P:** 雲毛・ふわふわの一体シルエットは、体の所属と関節を隠しやすい。毛房を独立球の集合として解釈すると、ビーズ状の頬、棚状の胸、房間の溝、頭と胴の二重ボリュームが生じやすい。まず連続した大きな身体の面を作り、局所の房は従属する起伏として扱う。表面の柔らかさと、身体全体が遅れて浮遊する挙動を混同しない。

## 2. Tripo入力と選択肢

**O [E3]:** 正式FrontとSideでも、同じ顔のランドマーク登録後に頭頂高さが一致せず、耳Sideも未較正カメラの解釈差が残った。**P:** Front / Side / Back / 3Qを、同じ単一立体・縮尺・接地・部品数・付け根から描く。左右という画像の向きとサービスのcamera slotを区別する。3Qは正面では見えない厚み・頬・耳根・背中の検査に使う。描けない背面を生成AI任せの確定情報にしない。

**H/O [E4]:** 背面候補は下半身の絞り、蹄形、立体接続で繰り返し不採用となり、三面入力案へ移行した。三面のサービス対応は当時UNKNOWNだった。**P:** 2Dの曖昧さは3Dの推測誤りへ直結する。不整合な四面を増やすより、正しい面と未定義箇所を明示してHuman判断へ戻す。

飾り・月・星を、身体の柄、身体に付く独立物、世界の浮遊物のいずれかへ明確に分類する。body-only入力では独立propを外しても、毛・角・翼・足・尾などIdentityに必要な解剖は消さない。**O [E5]:** 初期実装で月の浮き・二重投影、星の縁、側面の筋、顔境界が未解決だった。画像の色を全周へ投影しても、物の厚み・支持・裏側は完成しない。

**P: HD / Smart Mesh / Texture / Smart UVの判断は目的別に行う。** 本タスクは現行Tripo機能を照会しておらず、機能名から品質や保持保証を断定しない。

| 判断 | 先に確かめること | 避ける判断 |
| --- | --- | --- |
| HD等の高密度出力 | 低密度で顔・体積・所属が成立するか。追加密度が必要な具体箇所 | 頂点を増やせば誤った解剖も直ると期待 |
| Smart Mesh / remesh | 編集可能性、口角/瞼/付け根の辺配置、部品の融合・二重化 | quad数やmanifoldだけで変形可能と判定 |
| Texture | 形と必要な表情が先に成立し、隠れた口内にも色の計画があるか | 色のぼかしや陰影で形の失敗を隠す |
| Smart UV / UV変更 | 旧UV/材質/Weight/Morphとの対応、checker、再import差分 | 生成し直してもrigやUVが保持されると仮定 |

有料実行前に費用承認と入力を確定する。色戻しなら編集正本を保ち、戻りmeshで全置換せず、実測後に色のみ転送する方針を検討する [E6,E7]。

## 3. Blender / Rig / Motionの失敗を分離する

| 対象 | 再利用するチェック / 判断 |
| --- | --- |
| 耳の二重化 | 元meshに埋まった耳と追加耳が同時に残っていないか。左右各一つの付け根・厚いshell・内耳領域を確認。見えていない重複も切断面で点検する。今回取得した記録だけでは全試行の二重耳原因は確定できず、一般的な予防策Pとして扱う |
| 背中の谷 / 凹み | 正面輪郭から奥行きを押し出す方法の収束点、左右房の継ぎ目、法線と実形状を切り分ける。Back/Top/3Qの無地表示で確認。E5は背面中心へ深さが集まる不具合の修正を記録するが、全ての凹みが同じ原因とは断定しない |
| 羊毛の独立球化 | 頭・胸・胴の連続面と所属を先に決める。球の交差や房数の増加では量感・顎の境界を解けない [E1,E2] |
| 口・頬 | 口角に有限半径と広い頬/顎支持域、閉口時にも体積のある口内を設ける。固定スリットの狭い角へ大開口を集中させない。唇、固定笑顔線、舌、口内壁の二重表示/漏れも確認 [E6,E7] |
| 瞼・目 | Frontの可愛さに加え、Side/3Qの眼球の突出と眼窩への所属を確認。閉眼だけでなく視線・頬・口との独立合成、薄い境界の折れ筋を検査 [E3,E6] |
| 脚・蹄 | 腹に埋まらない支持肢、接地する足底、関節余裕、前後脚の所属を示す。足先を固定しても体重移動や座りの自然さを証明したことにはならない |
| 尻尾 | 胴体と別の所属・付け根を設計し、回転で破断/埋没しないか確認。浮いた毛塊と、胴に付く尾を区別する |
| 接地・重心 | 支持多角形、荷重移動、接触の連続性、片脚提供中の支えを確認。生成poseやcrouchを真の臀部支持座位として扱わない [E8] |

**T [E6,E7]:** 旧口角の最短辺は約0.23mm、最大方向別伸長は約11.186。狭い領域への旧顎場の移植では強圧縮と反転が残った。後の口構造再設計は、広い支持域・有限半径の唇・閉じた口内・主形状間の接続変更により、記録された開口/合成範囲の反転・退化を解消した。ただしHuman外観はPENDING、全Motion/runtime/deviceは未承認だった。

**P:** Rig/Weight/Shape Keysを追加しても、元の可動域や接続構造が不足すれば救済に限界がある。局所correctiveが別の合成で折れるなら、TopologyとNeutral構造へ戻る。Textureは厚み・接地・口内空間を作れない。rest/Basis一致やNeutral復帰差0は保護の証拠であり、ポーズ中のIdentityの証拠ではない。

**Geometry PASS ≠ Human可愛さPASS ≠ Motion/runtime PASS。UNKNOWN ≠ PASS。** 同じ保存済みassetからFront/Side/左右3Q、Neutral→中間→極値→復帰を描画し、量感・顔・重さ・自然さを承認資料と比較する。数値検査はその評価を補助する。

## 4. 工程と撤退判断

1. **デザインHuman Gate:** 魅力・Identity・体の所属を確定。多視点の矛盾を解く。手段の便利さだけで顔・比率を変えない。
2. **低コスト3D適性Gate:** 装飾・高密度・最終Textureより先に、単一立体の顔/体積/付け根/足底と代表変形を試す。Frontだけの合格で量産しない。
3. **代表Motion Gate:** 瞬き、独立視線、小/大開口、左右接触、座位遷移、片脚提供、復帰を、実際に必要な範囲で連続確認。単発画像だけで自然な支持を宣言しない。
4. **仕上げ/出力Gate:** UV checker、材質、保存再読込、GLB roundtrip、対象runtime/端末を変更リスクに応じて確認。各Gateの範囲とHuman未判定を分ける。

**P: 修正継続から設計見直しへ切り替える条件:** 同じ欠陥が再発する、修正が承認済み顔や量感を壊す、資料間の矛盾をgeometryで両立できない、corrective追加が別の合成を悪化させる、隠れた身体を磨いても見える魅力が改善しない場合。新しい証拠を増やさない反復は止め、原因・代案・小さな反証実験を示す。試行回数の普遍的な閾値は本記録からは定めない。

見直しは再設計の自動承認ではない。Humanに、保護するIdentity、未解決の立体矛盾、変更候補、見込む効果、撤退案を提示する。Humanが廃止とした対象を技術的な成功例のために復活させない。

## 5. 今後の新キャラ設計ルール / MVP

**避ける特徴 P:** 所属不明の毛塊、境目のない短脚、厚み不明の耳/翼、顔を隠す首毛、独立した飾りと模様の混同、Front/Sideで接続が違うデザイン、後付けrigだけで成立させる大開口、常に同じ角度でしか可愛くない顔。

**推奨する特徴 P:** 連続した柔らかい身体、明瞭な部位の付け根、少数の読みやすい量感階層、可動余裕のある付属部、正面と3Qの両方で魅力が保たれる眼窩/頬、支える足底、閉口でも立体のある口内。単純化のために既承認のJill/Pino/Shushuを改変する指示ではない。

MVPの最初に、(a) 顔のNeutral/閉眼/小開口の同一性、(b) Side/3Qの厚みと所属、(c) 座る/体重を移す/一肢を出す支持、(d) 合成と復帰、を小さな一体で確認する。可愛さ・Identityを上位目標に置き、Motion適性を早期に実証する。技術都合と衝突したら、方法を替えるかHumanにデザイン判断を返す。
